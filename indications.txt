💡 Proyecto: COBOL BANKING BATCH SYSTEM

Un sistema bancario empresarial de procesamiento nocturno, simulando un entorno real de mainframe.

OBJETIVO PROFESIONAL:
Demostrar competencias en desarrollo COBOL empresarial, procesamiento batch, manejo de ficheros, control de errores, reporting y arquitectura de sistemas legacy/mainframe.

ESCENARIO:
Durante la noche, el sistema procesa miles de movimientos bancarios, valida operaciones, actualiza saldos, calcula comisiones/intereses y genera informes detallados de resultados y errores.

Esto es considerablemente más atractivo para reclutadores COBOL que un CRUD tradicional.

2. PROCESO BATCH PRINCIPAL

Programa BANKPROC con flujo de procesamiento:

BANKPROC
   │
   ├── Inicialización (apertura de ficheros, lectura de parámetros)
   ├── Leer movimiento
   ├── Validar cuenta origen y destino
   ├── Validar importe y formato
   ├── Comprobar saldo disponible
   ├── Verificar estado de cuentas (activa/bloqueada)
   ├── Aplicar operación (débito/crédito)
   ├── Calcular comisión (reglas de negocio)
   ├── Actualizar saldos
   ├── Registrar en histórico
   └── Registrar resultado/error

EJEMPLO DE TRANSACCIÓN:

TRANSFERENCIA
Cuenta origen: 000123
Cuenta destino: 000987
Importe:        1250.00 €

VALIDACIONES:
✓ Ambas cuentas existen
✓ Cuentas activas (no bloqueadas)
✓ Saldo suficiente en cuenta origen
✓ Importe válido (positivo, formato correcto)
✓ No es movimiento duplicado
✓ Límites diarios no excedidos

POST-VALIDACIÓN:
- Actualizar saldo cuenta origen (-1250.00€)
- Actualizar saldo cuenta destino (+1250.00€)
- Calcular comisión (ej: 0.1% = 1.25€)
- Registrar en histórico con timestamp
- Generar registro de auditoría

5. JCL (JOB CONTROL LANGUAGE)

Componente CRÍTICO para puestos COBOL/mainframe.

JOB PRINCIPAL:
//BANKJOB  JOB (ACCT),'DAILY BANKING',
//             CLASS=A,MSGCLASS=X,NOTIFY=&SYSUID
//*
//*  DAILY BANKING BATCH PROCESSING
//*  RUNS NIGHTLY AT 02:00
//*
//STEP01   EXEC PGM=BANKPROC,REGION=4M
//STEPLIB  DD DSN=BANK.LOADLIB,DISP=SHR
//INPUT    DD DSN=BANK.MOVEMENTS,DISP=SHR
//ACCOUNTS DD DSN=BANK.ACCOUNTS,DISP=SHR
//CLIENTS  DD DSN=BANK.CLIENTS,DISP=SHR
//REPORT   DD DSN=BANK.REPORT(&DATE),
//            DISP=(NEW,CATLG,DELETE),
//            DCB=(RECFM=FB,LRECL=132,BLKSIZE=1320)
//ERRORS   DD DSN=BANK.ERRORS(&DATE),
//            DISP=(NEW,CATLG,DELETE)
//AUDIT    DD DSN=BANK.AUDIT(&DATE),
//            DISP=(NEW,CATLG,DELETE)
//SYSOUT   DD SYSOUT=*
//SYSIN    DD *
  RUNDATE=20260926
  MODE=PRODUCTION
/*

JOB DE ORDENACIÓN (si aplica):
//SORTJOB  JOB ...
//STEP01   EXEC PGM=SORT
//SYSOUT   DD SYSOUT=*
//SORTIN   DD DSN=BANK.MOVEMENTS,DISP=SHR
//SORTOUT  DD DSN=BANK.MOVEMENTS.SORTED,DISP=(NEW,CATLG)
//SYSIN    DD *
  SORT FIELDS=(1,10,CH,A)
/*

CONCEPTOS A DEMOSTRAR:
- Job cards y parámetros
- EXEC PGM y parámetros
- DD statements (DISP, DSN, DCB)
- SYSIN / SYSOUT
- Paso de parámetros al programa
- Catalogación de ficheros
- Variables de sistema (&DATE, &SYSUID)
- COND codes y manejo de condiciones

ESTO DEMUESTRA:
COBOL + procesamiento batch + ficheros + JCL + arquitectura empresarial

6. SQL / DB2 (FASE 2)

Integración con base de datos DB2 usando Embedded SQL:

ARQUITECTURA:
COBOL → DB2 → TABLAS (CLIENTES, CUENTAS, MOVIMIENTOS)

EJEMPLO DE CÓDIGO:
EXEC SQL
    SELECT BALANCE, STATUS
      INTO :WS-BALANCE, :WS-STATUS
      FROM ACCOUNTS
     WHERE ACCOUNT_ID = :WS-ACCOUNT-ID
END-EXEC

EXEC SQL
    UPDATE ACCOUNTS
       SET BALANCE = :WS-NEW-BALANCE
     WHERE ACCOUNT_ID = :WS-ACCOUNT-ID
END-EXEC

EXEC SQL
    INSERT INTO TRANSACTIONS
    (TRANS_ID, ACCOUNT_ID, AMOUNT, TRANS_DATE, TYPE)
    VALUES (:WS-TRANS-ID, :WS-ACCOUNT-ID, :WS-AMOUNT,
            CURRENT TIMESTAMP, :WS-TYPE)
END-EXEC

CONCEPTOS A DEMOSTRAR:
- DECLARE SECTION para variables host
- SELECT INTO
- INSERT, UPDATE, DELETE
- Manejo de SQLCA (SQL Communication Area)
- SQLCODE y SQLSTATE
- Cursores para múltiples filas
- COMMIT y ROLLBACK
- Manejo de transacciones

ESTO DEMUESTRA:
COBOL + JCL + DB2 = Stack empresarial completo

EJEMPLO DE COPYBOOK:
* BANK-ERRORS.cpy
       05 ERR-CODE           PIC X(4).
           88 ERR-NONE       VALUE "0000".
           88 ERR-ACCOUNT    VALUE "E001".
           88 ERR-BALANCE    VALUE "E002".
           88 ERR-BLOCKED    VALUE "E003".
           88 ERR-AMOUNT     VALUE "E004".
           88 ERR-DUPLICATE  VALUE "E005".

Uso en programa principal:
       COPY BANK-ERRORS.
       
       IF ERR-CODE = ERR-ACCOUNT
           PERFORM HANDLE-ACCOUNT-ERROR
       END-IF

Enterprise banking batch-processing system built with COBOL and JCL, demonstrating legacy/mainframe development practices.

## 🎯 Overview

Simulated nightly batch processing system that handles thousands of banking transactions, validates operations, updates balances, calculates commissions/interest, and generates detailed reports.
